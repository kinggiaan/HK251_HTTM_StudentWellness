# AI Integration Guide

## 1. Introduction

This guide details how the frontend application integrates with the backend's Artificial Intelligence and Machine Learning (AI/ML) services. The system uses AI to predict student mental health risks, analyze trends, and provide actionable insights for consultants and teachers.

## 2. AI/ML Features in Frontend

The frontend exposes the following AI capabilities:
1.  **Risk Prediction:** Displaying AI-calculated risk scores for students.
2.  **Model Management:** Interface for Data Scientists to train, evaluate, and deploy ML models.
3.  **Dataset Management:** Uploading and managing datasets used for training.
4.  **Analytics Dashboard:** Visualizing AI-derived insights (e.g., risk distribution, factor analysis).

## 3. Data Models

### 3.1 ML Model (`MLModel`)
Represents a machine learning model in the system.
- **Properties:** `id`, `modelName`, `modelType` (classification/regression), `version`, `accuracy`, `status` (training/trained/deployed), `hyperparameters`.
- **Usage:** Used in the Data Scientist Dashboard to track model performance and lifecycle.

### 3.2 Mental Health Record (`MentalHealthRecord`)
Contains the assessment data and the AI prediction.
- **Properties:** `riskScore` (0-100), `riskLevel` (low/medium/high/critical), `predictedRisk` (AI output), `assessmentType` ('ml_prediction' for AI-generated records).
- **Usage:** Displayed in Student Profiles and Risk Assessment views.

## 4. Service Layer Integration

The frontend communicates with the AI backend via dedicated service modules.

### 4.1 `src/services/mlModels.ts`
Handles operations related to the ML models themselves.

| Function | Description | Endpoint |
| :--- | :--- | :--- |
| `listModels(params)` | Fetches a paginated list of ML models. | `GET /ml/models` |
| `createModel(input)` | Defines a new model configuration. | `POST /ml/models` |
| `trainModel(id, params)` | Triggers the training process for a model. | `POST /ml/models/:id/train` |
| `deployModel(id)` | Promotes a model to be the active predictor. | `POST /ml/models/:id/deploy` |
| `deleteModel(id)` | Removes a model. | `DELETE /ml/models/:id` |

### 4.2 `src/services/datasets.ts`
Handles the datasets used for training models.

| Function | Description | Endpoint |
| :--- | :--- | :--- |
| `listDatasets()` | Lists available training datasets. | `GET /ml/datasets` |
| `uploadDataset(file)` | Uploads a CSV/JSON dataset. | `POST /ml/datasets/upload` |

### 4.3 `src/services/mentalHealth.service.ts`
Retrieves the predictions generated by the deployed model.

| Function | Description | Endpoint |
| :--- | :--- | :--- |
| `listByStudent(id)` | Gets health records, including AI predictions. | `GET /students/:id/health-records` |

## 5. User Workflows

### 5.1 Data Scientist Workflow
1.  **Upload Data:** User goes to "Datasets" tab -> Uploads a CSV file -> `datasets.uploadDataset()`.
2.  **Configure Model:** User clicks "New Model" -> Fills form (Algorithm, Hyperparameters) -> `mlModels.createModel()`.
3.  **Train Model:** User selects a model -> Clicks "Train" -> Selects Dataset -> `mlModels.trainModel()`.
    *   *UI Feedback:* The model status changes to `training`. The UI polls or refreshes to check for `trained` status.
4.  **Evaluate:** User views model details (Accuracy, F1 Score) returned by the backend.
5.  **Deploy:** User clicks "Deploy" -> `mlModels.deployModel()`. This model is now used for all new student assessments.

### 5.2 Consultant/Teacher Workflow
1.  **View Risk:** User views the Student Dashboard.
2.  **Fetch Data:** Frontend calls `mentalHealth.service.listByStudent()`.
3.  **Display:** If a record has `assessmentType: 'ml_prediction'`, it is highlighted as an AI Insight. The `riskScore` determines the color coding (Green/Yellow/Red).

## 6. Error Handling & Edge Cases
- **Training Failures:** If training fails, the model status becomes `failed`. The UI displays the error message provided by the backend.
- **No Active Model:** If no model is deployed, the prediction features may be disabled or show a "System Calibration Needed" warning.
- **Data Privacy:** Student names are anonymized in the training datasets (handled by backend before storage).

## 7. Future Improvements
- **Real-time Training Progress:** Implement WebSockets to show a progress bar during model training.
- **Explainability (XAI):** Visualize *why* a model predicted a high risk (e.g., "High sleep deprivation contributed 40% to risk score").
